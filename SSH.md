# Генерация SSH-ключа в Windows и добавление его на сервер Ubuntu

Процесс настройки беспарольного доступа по ключам состоит из двух шагов: генерация пары ключей на Windows и прописка публичной части на сервере VPS.

---

### Шаг 1: Генерация ключа Ed25519 на Windows

Современный стандарт — ключи алгоритма `Ed25519`. Они быстрее, безопаснее и короче, чем старый формат RSA.

1. Откройте **PowerShell** или **Командную строку** на Windows.
2. Введите команду для генерации:
   ```cmd
   ssh-keygen -t ed25519
   ```
3. Нажмите `Enter` на первый запрос (чтобы сохранить ключ в стандартную папку `C:\Users\<Ваш_Юзер>\.ssh\id_ed25519`).
4. На запросы ввода пароля (`Enter passphrase`) **дважды нажмите `Enter`**, оставив поле пустым. Это необходимо, чтобы VS Code и Multicoder подключались автоматически без ручного ввода пароля.

*Результат:* В вашей Windows-системе появились файлы `id_ed25519` (приватный ключ для VS Code) и `id_ed25519.pub` (публичный ключ для сервера).

---

### Шаг 2: Вывод публичного ключа на экран Windows

Прямо в консоли Windows выполните команду, чтобы отобразить содержимое вашего публичного ключа:
```cmd
type %USERPROFILE%\.ssh\id_ed25519.pub
```
* **Выделите и скопируйте** появившуюся строку (она выглядит примерно так: `ssh-ed25519 AAAAC3NzaC1lZDI1NTE5... user@windows-pc`).

---

### Шаг 3: Добавление ключа на сервер Ubuntu

Теперь нужно зайти на ваш сервер под пользователем `ubuntu` (используя старый способ — пароль) и разрешить вход по вашему новому Windows-ключу.

1. Откройте конфигурационный файл ключей на сервере:
   ```bash
   nano ~/.ssh/authorized_keys
   ```
2. Опуститесь стрелочками на клавиатуре в самый низ файла.
3. Вставьте скопированную из Windows строку с новой строчки.
4. Сохраните изменения: нажмите `Ctrl + O`, затем `Enter`.
5. Выйдите из редактора: нажмите `Ctrl + X`.

---

### Шаг 4: Настройка прав доступа на сервере (Критично)

Linux очень строг к безопасности. Если у папки `.ssh` или файла `authorized_keys` будут слишком открытые права, сервер проигнорирует ключ и продолжит требовать пароль. Выполните на сервере две команды:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

---

### Финал: Корректировка пути в VS Code `settings.json`

Так как мы создали более надежный ключ `ed25519`, в настройках локального VS Code (в параметрах Multicoder) укажите правильное имя файла:

```json
"multicoder.ssh.privateKeyPath": "\${userHome}/.ssh/id_ed25519",
```


# Настройка файла `config` на Windows при использовании нескольких SSH-ключей

Если у вас несколько ключей для разных серверов или GitHub, вам нужно создать специальный файл конфигурации SSH на вашей Windows-машине. Он будет автоматически подставлять правильный ключ для каждого конкретного сервера.

---

### Шаг 1: Создание локального файла `config`

1. На Windows перейдите в папку `C:\Users\<Ваш_Юзер>\.ssh\`.
2. Создайте там обычный текстовый файл с именем **`config`** (без расширения `.txt`, имя должно быть строго маленькими буквами).

---

### Шаг 2: Наполнение файла `config`

Откройте созданный файл через Блокнот или VS Code и пропишите правила для ваших серверов. Вот пример, как разделить ключи для рабочего сервера, домашнего сервера и GitHub:

```text
# --- ВАШ СЕРВЕР С AI-АГЕНТОМ ---
Host vps-openhands
    HostName 81.0.94.6
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes

# --- ВТОРОЙ СЕРВЕР (ПРИМЕР) ---
Host second-server
    HostName 192.168.1.50
    User root
    IdentityFile ~/.ssh/id_rsa_second
    IdentitiesOnly yes

# --- НАСТРОЙКА ДЛЯ GITHUB (ПРИМЕР) ---
Host github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github
    IdentitiesOnly yes
```

**Разбор параметров:**
*   `Host`: Удобный псевдоним (алиас) для подключения. Вы можете назвать его как угодно (например, `vps-openhands`).
*   `HostName`: Реальный IP-адрес или домен сервера.
*   `User`: Имя пользователя по умолчанию (`ubuntu`, `root` и т.д.).
*   `IdentityFile`: **Прямой путь к конкретному приватному ключу**, который нужно использовать для этого хоста.
*   `IdentitiesOnly yes`: Важная директива. Она запрещает SSH перебирать все ключи подряд, заставляя использовать строго тот, что указан в `IdentityFile` (это защищает от блокировки сервером за перебор ключей).

---

### Шаг 3: Как это упрощает работу

1. **В консоли Windows** теперь не нужно вводить длинные команды с путями к ключам. Достаточно написать псевдоним:
   ```cmd
   ssh vps-openhands
   ```
   *Система сама посмотрит в конфиг, возьмет IP `81.0.94.6`, юзера `ubuntu` и ключ `id_ed25519`.*

2. **В настройках VS Code (`settings.json` для Multicoder)**. Локальный конфигурационный файл SSH имеет приоритет. В плагине Multicoder вы можете продолжать использовать явное указание ключа (как мы настроили в Шаге 4), либо, если плагин поддерживает чтение системного конфига, он сам подставит нужные данные по имени хоста. Для максимальной надежности в Multicoder мы оставляем явный путь к файлу:
   ```json
   "multicoder.ssh.privateKeyPath": "\${userHome}/.ssh/id_ed25519",
   ```
